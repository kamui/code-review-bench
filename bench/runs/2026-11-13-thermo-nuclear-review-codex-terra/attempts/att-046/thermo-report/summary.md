[P2] Preserve argument-order independence for names with large numeric suffixes — `src/validation/rules/OverlappingFieldsCanBeMergedRule.ts:649`

Sorting the synthetic object uses `sortValueNode`, whose `naturalCompare` converts digit runs to JavaScript numbers. Distinct names such as `a9007199254740992` and `a9007199254740993` therefore compare equal because of integer precision loss. Stable sorting retains their original order, so two occurrences of the same field with identical arguments in reverse order stringify differently and are rejected as conflicting. For example, with `type Query { f(a9007199254740992: Int, a9007199254740993: Int): Int }`, `{ f(a9007199254740992: 1, a9007199254740993: 2) f(a9007199254740993: 2, a9007199254740992: 1) }` produces a differing-arguments error even though argument order is insignificant. The previous name-based lookup accepted this valid operation. A focused validation test reproduced the error.
