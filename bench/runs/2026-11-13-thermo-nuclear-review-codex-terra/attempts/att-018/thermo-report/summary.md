[P2] Preserve the existing context when a middleware passes a nullish override — `packages/server/src/core/internals/utils.ts:21-23`

`Overwrite` also combines middleware context types, but this branch replaces an object context with `null` or `undefined`. At runtime, `next({ ctx })` merges the override with the existing context using object spread, so a nullish override leaves the existing context intact. For example, with a root context `{ user: { id: string } | null; traceId: string }`, middleware returning `next({ ctx: ctx.user && { user: ctx.user } })` is valid, but a following resolver's `ctx.traceId` now fails to type-check because `ctx` is inferred as possibly null. Before this change the null branch retained the root context's properties. The same mismatch can propagate through middleware chains, breaking existing procedures even though their runtime context remains valid.
