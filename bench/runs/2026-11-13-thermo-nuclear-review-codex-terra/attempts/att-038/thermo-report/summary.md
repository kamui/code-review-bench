[P2] Specify the required ordering around compinit (FAQ.md:124-135). The two setup methods require opposite ordering relative to zsh's completion initialization, but the instructions do not mention it. `compinit` scans `fpath` when it runs, so adding the directory afterward does not register the newly generated completion. Conversely, sourcing the script before `compinit` finds no `compdef`, takes the fallback at rg.zsh:441-442 and calls `_rg` outside a completion context, producing an error instead of registering it. I reproduced both orderings in clean zsh sessions: a completion directory added after `compinit` was not registered, and sourcing the script before initialization failed; sourcing after initialization succeeded. Tell users to add the directory before `compinit`, or to source the generated script after it.

[P2] Remove the shell prompt from the zshrc snippet (FAQ.md:131-135). The text tells users to add the displayed line to `.zshrc`, but the line begins with `$ `, which is a prompt marker rather than zsh syntax. Copied as instructed, zsh tries to execute a command named `$` and reports `command not found: $`, so the completion script is never sourced. A clean zsh session reproduces this with the displayed command form.
