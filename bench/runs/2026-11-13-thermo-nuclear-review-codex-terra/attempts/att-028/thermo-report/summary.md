# Review findings

[P1] Preserve support for legacy protobuf messages in the default codec — `encoding/proto/proto.go:41` (also line 49). The old `github.com/golang/protobuf/proto.Message` interface accepts messages generated by older versions of protoc-gen-go, which implement Reset, String and ProtoMessage but not ProtoReflect. Changing the assertion to the v2 interface rejects these messages on both marshal and unmarshal. Consequently existing clients and servers using those generated stubs fail every RPC with a codec error after upgrading grpc-go. A local legacy-message reproduction returned `failed to marshal, message is *main.Legacy, want proto.Message`; adapting v1 messages before calling the v2 API preserves compatibility.

[P2] Unwrap legacy messages returned by Status.Details — `internal/status/status.go:158-163`. Previously `ptypes.UnmarshalAny` with `DynamicAny` converted the resolved message back to its v1 type before returning it. `any.UnmarshalNew` instead returns a v2 reflection wrapper for a registered legacy-only message, and appending that wrapper changes the public `Details` result. For example, `WithDetails(&Legacy{})` succeeds, but a subsequent `Details()[0].(*Legacy)` assertion now fails (or panics if unchecked), so callers cannot consume their existing custom error details. A local registered v1 message reproduced the returned type as `*impl.messageIfaceWrapper`; converting the result through `protoadapt.MessageV1Of` restores the original concrete type.

Validation: A focused local Go reproduction exercised the default codec and a registered legacy status detail. The checkout was not modified.
