# Thermo-nuclear review: grpc/grpc-go#6919 (migrate to google.golang.org/protobuf)

Range reviewed: `5051eeae..b8374114`. `go build ./xds/... ./internal/... ./status/...` succeeds.

## Finding 1 (High): default proto codec stops accepting legacy (v1-only) messages

**File:** `encoding/proto/proto.go`, lines 25-52 (`codec.Marshal` and `codec.Unmarshal`).

The change swaps the import `github.com/golang/protobuf/proto` for `google.golang.org/protobuf/proto`. The type assertions `v.(proto.Message)` stay as they were.

- Before the change, `proto.Message` was the v1 interface (`Reset`, `String`, `ProtoMessage`). Any message generated by old protoc-gen-go (golang/protobuf older than 1.4) satisfied it. So did gogo-style or hand-written v1 messages.
- After the change, `proto.Message` is `protoreflect.ProtoMessage`, which requires `ProtoReflect()`. A message that has only the v1 methods now fails the assertion.
- The old code let `golang/protobuf`'s `proto.Marshal` wrap such messages with `protoimpl.X.ProtoMessageV2Of`. The new code has no equivalent.

**Failure:** this codec is the default for every gRPC call. A user who upgrades and sends or receives a legacy-generated message gets `failed to marshal, message is *pkg.Msg, want proto.Message` or `failed to unmarshal, ...`. Every RPC using that type then fails at runtime. There is no compile-time signal, because the codec takes `any`. The PR does not mention the break, and no test covers it. The fix is to accept v1 messages and convert them, for example with `protoadapt.MessageV2Of` / `protoimpl.X.ProtoMessageV2Of`.

## Finding 2 (Medium): LRS error message formats the wrong, nil error

**File:** `xds/internal/xdsclient/transport/loadreport.go`, lines 173-178 (`recvFirstLoadStatsResponse`).

```go
rInterval := resp.GetLoadReportingInterval()
if rInterval.CheckValid() != nil {
    return nil, 0, fmt.Errorf("invalid load_reporting_interval: %v", err)
}
```

The original code was `interval, err := ptypes.Duration(...)`, so `err` held the validation error. The new code discards the result of `CheckValid()` and formats the outer `err` from `stream.Recv()`. That `err` is `nil` at this point, because the earlier `if err != nil` returned.

**Failure:** when the management server sends an invalid `load_reporting_interval`, the error reads `invalid load_reporting_interval: <nil>`. The actual cause (out of range or negative nanos) is lost. The returned error is still non-nil, so the stream is still rejected. Only the diagnostic is broken. The fix is `if err := rInterval.CheckValid(); err != nil { ... %v, err }`.

## Finding 3 (Low/Medium): unrelated dependency downgrade in `test/tools`

**Files:** `test/tools/go.mod` (lines 5-17) and `test/tools/go.sum`.

The change to switch `protoc-gen-go` to `google.golang.org/protobuf/cmd/protoc-gen-go` is legitimate. The same go.mod edit also downgrades `golang.org/x/tools` from v0.17.0 to v0.14.0. It drops `golang.org/x/sync`, adds `golang.org/x/sys v0.13.0`, and rewrites the go.sum entries to match. This looks like an accidental artifact of a stale or conflicting `go mod tidy` and has nothing to do with the protobuf migration.

**Impact:** the pinned `goimports` and `staticcheck` toolchain used by `vet.sh` / `regenerate.sh` moves to an older, unreviewed version. Lint behaviour and the Go-toolchain compatibility of those tools can change. The fix is to keep `x/tools` v0.17.0 and let tidy only drop `golang/protobuf`.

## Notes checked and not reported

- `internal/status` `WithDetails` / `Details`: the switch to `protoadapt.MessageV1` / `anypb` / `UnmarshalNew` is source compatible for generated messages. Only the error text for an invalid type URL changes, and the tests were updated.
- `internal/pretty`: `protojson` with `Indent` produces indented output, which is acceptable.
- `balancer/rls` `convertDuration`: `AsDuration()` plus `CheckValid()` is equivalent for non-nil input, and the nil case is guarded earlier.
- `examples/go.mod`: moving `golang/protobuf` to indirect is consistent with the code changes.
