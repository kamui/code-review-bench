# 01 — The `any` → `proto.Message` boundary (findings 1, 2, 3, 6)

## What changed structurally

`github.com/golang/protobuf/proto.Message` is `protoiface.MessageV1` (`Reset()`, `String()`, `ProtoMessage()`). `google.golang.org/protobuf/proto.Message` is `protoreflect.ProtoMessage` (`ProtoReflect()`). Code generated by protoc-gen-go v1.4+ implements both, which is why the repository's own tests pass. Messages from gogo/protobuf, from older generators, or written by hand implement only the first.

Changing the import line therefore changes the meaning of every `x.(proto.Message)` on an `any` value. The diff has four such boundaries in non-test code, and after the change each one behaves differently:

| Site | Accepts v1-only at base | At head |
|---|---|---|
| `encoding/proto/proto.go:41`, `:49` (codec) | yes | no — returns an error |
| `internal/binarylog/method_logger.go:242`, `:282` | yes | no — logs empty payload |
| `internal/pretty/pretty.go:39` | yes | yes — separate duplicated branch |
| `internal/status/status.go:134`/`:158` | in and out as v1 | in as v1, out as v2 wrapper |

Four sites, four policies. That inconsistency is the structural finding; the individual regressions follow from it.

## Reproduction

Scratch sources live in `clone-work/scratch/`. "Base" runs use the same overlay plus the `main` version of the file under test (`git show main:<path>`).

### Finding 6 — `pretty.ToJSON`

Read at head, `internal/pretty/pretty.go:39-61`:

```go
case protov1.Message:
	mm := protojson.MarshalOptions{Indent: jsonIndent}
	ret, err := mm.Marshal(protov1.MessageV2(ee))
	if err != nil {
		// This may fail for proto.Anys, ...
		return fmt.Sprintf("%+v", ee)
	}
	return string(ret)
case protov2.Message:
	mm := protojson.MarshalOptions{
		Multiline: true,
		Indent:    jsonIndent,
	}
	ret, err := mm.Marshal(ee)
	if err != nil {
		// This may fail for proto.Anys, ...
		return fmt.Sprintf("%+v", ee)
	}
	return string(ret)
```

`protojson.MarshalOptions.Indent` is documented as implying multiline when non-empty, so the option sets are equivalent. Because every generated message satisfies the first case, the second case is reached only by v2-only messages such as `dynamicpb`. `go list -deps ./internal/pretty | grep -c github.com/golang/protobuf` prints `1` at head.

Verification status: **confirmed by reading; proposal confirmed by execution** (below).

## Worked code-judo proposal

The move is to stop asking "is this the right `proto.Message`?" at each site and instead normalise once.

In `encoding/proto/proto.go` (the canonical owner of "what counts as a proto message for gRPC"):

```go
func (codec) Marshal(v any) ([]byte, error) {
	vv := messageV2Of(v)
	if vv == nil {
		return nil, fmt.Errorf("failed to marshal, message is %T, want proto.Message", v)
	}
	return proto.Marshal(vv)
}

func (codec) Unmarshal(data []byte, v any) error {
	vv := messageV2Of(v)
	if vv == nil {
		return fmt.Errorf("failed to unmarshal, message is %T, want proto.Message", v)
	}
	return proto.Unmarshal(data, vv)
}

func messageV2Of(v any) proto.Message {
	switch v := v.(type) {
	case protoadapt.MessageV1:
		return protoadapt.MessageV2Of(v)
	case protoadapt.MessageV2:
		return v
	}
	return nil
}
```

`protoadapt.MessageV2Of` is the identity for messages that already implement v2, so there is no cost on the common path beyond the type switch.

In `internal/status/status.go`, close the loop that `WithDetails` opened:

```go
detail, err := any.UnmarshalNew()
if err != nil {
	details = append(details, err)
	continue
}
// WithDetails accepts MessageV1; return the same kind of value. This
// unwraps v1-only messages and is the identity for generated code.
details = append(details, protoadapt.MessageV1Of(detail))
```

In `internal/pretty/pretty.go`, normalise and keep one proto case:

```go
func ToJSON(e any) string {
	if m, ok := e.(protoadapt.MessageV1); ok {
		e = protoadapt.MessageV2Of(m)
	}
	switch ee := e.(type) {
	case proto.Message:
		ret, err := protojson.MarshalOptions{Indent: jsonIndent}.Marshal(ee)
		if err != nil {
			// This may fail for proto.Anys, ...
			return fmt.Sprintf("%+v", ee)
		}
		return string(ret)
	default:
		...
	}
}
```

That removes roughly ten duplicated lines and the `protov1`/`protov2` aliasing, and it is the change that lets the file stop importing `github.com/golang/protobuf`.

In `internal/binarylog/method_logger.go`, the client and server entries should share the payload step rather than each repeating the assertion chain:

```go
func marshalPayload(msg any) []byte {
	switch m := msg.(type) {
	case protoadapt.MessageV1:
		return marshalProto(protoadapt.MessageV2Of(m))
	case protoadapt.MessageV2:
		return marshalProto(m)
	case []byte:
		return m
	}
	grpclogLogger.Infof("binarylogging: message to log is neither proto.message nor []byte")
	return nil
}
```

If a second internal consumer of `messageV2Of` is preferred over repeating the type switch, put the helper in a small internal package and have `encoding/proto`, `internal/binarylog` and `internal/pretty` import it. Three consumers is enough to justify one definition.

## Existing tests at head

`go test -count=1 ./encoding/proto ./status ./internal/binarylog ./internal/pretty/... ./internal/status/...` passes at head. That is expected and is the point: no test in the repository uses a v1-only message, so nothing guards the behaviour that changed. Each fix above should land with one.
