The framework has no runtime dependencies. Its TypeScript source was imported directly: no install and no build of the

How a probe runs (run.sh): the probe is copied to <checkout>/_probe/, then run with "bun run <probe>.ts", or bundled with
  bun build <probe>.ts --target=node --outfile=<probe>.node.mjs
and the bundle run with "node --expose-gc". Nothing in Hono or the platform is replaced; behaviour.ts wraps the platform's
formData() with a counter that calls the original.

What the figures are:
  time.ts: performance.now() around the one awaited c.req.parseBody() inside the handler (or around the exported
    parseBody() for a plain Request). Every request is new, so nothing is remembered when the read starts. A process sends
    one request whose time is reported as "cold", then WARMUP unmeasured ones, then REQUESTS measured ones, and prints
    their median, lowest and highest. Requests per process: 20000 after 2000 for the small forms, 100 after 5 for 1 MB,
    40 after 4 for 8 MB, 15 after 2 for 32 MB, 6 after 1 for 100 MB, 5 after 1 for 128 MB.
    "stream": the body is a ReadableStream made in the same process in 64 KiB chunks while it is read, so the time
    includes making the chunks, the same at both commits. "bytes": one Uint8Array prepared once per process.
    The tables give, per cell, the median over processes of each process's median, then [lowest - highest] of those
    process medians. base and head: 5 processes per cell; each patch: 3 (streamed bodies only).
  net-server.ts: a real HTTP upload over 127.0.0.1 with curl -F to Bun.serve (bun) or node:http with a minimal adapter
    (node); the time inside c.req.parseBody() and curl's total time per upload; 6 uploads per server process, 3 server
    processes per cell. The first upload of each process is reported apart.
  memory.ts: resident set size in MiB above the process's baseline; peak from process.resourceUsage().maxRSS, held
    after the read and a forced collection while the request and the result are alive. One streamed 100 MB upload per
    process, 3 processes per cell.
  stages.ts: the platform's own calls, no Hono code: request.formData() against request.arrayBuffer(), new Response(bytes)
    and response.formData() in turn, on one prepared 8 or 100 MB multipart body.
Not run: Deno, Cloudflare Workers (workerd), an upload over a real network link (only 127.0.0.1), @hono/node-server (not
  among the project's dependencies), several requests at once, a process under a memory limit, any production application.
