## 1. Component Layer Model

Four layers. A component belongs to exactly one, and the boundary rules are enforced in review.

```
src/components/
├── ui/          shadcn/ui primitives — generic, zero business logic
├── common/      cross-role composites — used by 2+ roles
├── consumer/    consumer-only composites
├── merchant/    merchant-only composites
├── processor/   processor-only composites
├── admin/       admin-only composites
└── features/    feature-scoped composites bound to one domain concern
```

### 1.1 Layer Rules

| Layer | May import from | May contain | Must never contain |
| --- | --- | --- | --- |
| `ui/` | nothing but `@/lib/utils` and the underlying primitive lib | styling, variants, a11y wiring | Cirquo domain types, Convex hooks, Bahasa Indonesia copy, formatting helpers |
| `common/` | `ui/`, `@/lib/*` | layout, formatting, generic domain display | Convex queries/mutations, route knowledge |
| `{role}/` | `ui/`, `common/`, `features/`, `@/lib/*` | role-specific composition, role copy | Another role's components |
| `features/` | `ui/`, `common/`, `@/lib/*` | domain logic, Convex hooks, a bounded concern | Route-level layout, cross-feature imports |

**The hard rule for `ui/`:** these files are generated by the shadcn CLI and may be regenerated. **Never add business logic to them.** If a `Badge` needs to know about `RescueItemStatus`, you do not modify `badge.tsx` — you build `StatusBadge` in `common/` that composes `Badge`.

### 1.2 Placement Decision Table

| Question | Answer | Destination |
| --- | --- | --- |
| Is it a generic, domain-free primitive from shadcn? | Yes | `ui/` |
| Does it reference a Cirquo domain type (`RescueItem`, `LedgerEvent`, `RecoveryBatch`)? | Yes → continue | not `ui/` |
| Is it used by two or more roles? | Yes | `common/` |
| Does it own data fetching for one bounded domain concern? | Yes | `features/{concern}/` |
| Is it used by exactly one role and is it presentational? | Yes | `{role}/` |
| Is it used once, inside a single page, with no reuse prospect? | Yes | Keep inline in the page file until a second use appears |

**Worked examples:**

| Component | Layer | Reason |
| --- | --- | --- |
| `Button` | `ui/` | Generic primitive |
| `StatusBadge` | `common/` | Domain-aware but used by all four roles |
| `RescueItemCard` | `common/` | Consumer explore, merchant list preview, admin moderation |
| `PickupCodeCard` | `consumer/` | Only the consumer sees their own code |
| `PickupCodeInput` | `merchant/` | Only the merchant verifies |
| `IntakeForm` | `processor/` | Processor-only |
| `LedgerTimeline` | `common/` | All four roles read it |
| `MapView` | `features/map/` | Owns Mapbox lifecycle, geolocation, clustering |
| `ImpactBreakdownBar` | `common/` | Signature visual, every role |
| `RoleGuard` | `common/` | Route infrastructure used by every role group |

### 1.3 File Conventions

| Item | Convention | Example |
| --- | --- | --- |
| File name | `kebab-case.tsx` | `rescue-item-card.tsx` |
| Component name | `PascalCase` | `RescueItemCard` |
| Props interface | `{Component}Props`, exported | `export interface RescueItemCardProps` |
| Export | Named, not default | `export function RescueItemCard(...)` |
| Sub-components | Same file if only used together | `RescueItemCard` + `RescueItemCardSkeleton` |
| Variants | `cva` colocated in the same file | `const cardVariants = cva(...)` |
| Types | Import from `@/types`, never redeclare | `import type { RescueItem } from "@/types"` |
| Formatting | Import from `@/lib/format`, never inline `Intl` | `formatWeight(grams)` |

## 2. The `render` Prop Pattern

**Critical and easy to get wrong.** These shadcn components are built on `@base-ui/react`, which uses a **`render` prop** for polymorphism — not Radix's `asChild`.

### 2.1 Correct Usage

```tsx
// ✅ Button rendering as a React Router Link
<Button render={<Link to="/explore" />}>Jelajahi</Button>

// ✅ SheetTrigger rendering as a Button
<SheetTrigger render={<Button variant="outline" size="icon" aria-label="Buka menu" />}>
  <Menu className="size-5" />
</SheetTrigger>

// ✅ Button as an external anchor
<Button variant="link" render={<a href="https://midtrans.com" target="_blank" rel="noreferrer" />}>
  Bantuan pembayaran
</Button>

// ✅ DropdownMenuTrigger as a ghost icon Button
<DropdownMenuTrigger render={<Button variant="ghost" size="icon" aria-label="Aksi lainnya" />}>
  <MoreVertical className="size-4" />
</DropdownMenuTrigger>
```

### 2.2 Incorrect Usage

```tsx
// ❌ asChild — not supported by these components
<Button asChild><Link to="/explore">Jelajahi</Link></Button>

// ❌ Nested interactive elements: a <button> wrapping an <a>. Invalid HTML,
//    breaks keyboard navigation and screen-reader announcement.
<Button><Link to="/explore">Jelajahi</Link></Button>

// ❌ Children inside the render element. Children belong on the outer component.
<Button render={<Link to="/explore">Jelajahi</Link>} />

// ❌ Manually re-applying button classes to a Link
<Link to="/explore" className="bg-primary text-primary-foreground h-9 px-4 rounded-md">
  Jelajahi
</Link>
```

### 2.3 How It Works

The `render` prop receives a React element. The component merges its own props — `className`, `ref`, event handlers, ARIA attributes, `data-*` state — into that element and renders it in place of its default tag. Children continue to be supplied to the **outer** component.

| Aspect | `asChild` (Radix classic) | `render` (base-ui, used here) |
| --- | --- | --- |
| Syntax | `<Button asChild><Link/></Button>` | `<Button render={<Link/>}>` |
| Children | Inside the child element | On the outer component |
| Ref merging | via `Slot` | via `render` element cloning |
| Type safety | Weaker — children are `ReactNode` | Stronger — `render` is `ReactElement` |
| Multiple children | Runtime error | Not possible by construction |

### 2.4 Where It Applies

| Component | Slots accepting `render` |
| --- | --- |
| `Button` | root |
| `SheetTrigger` / `SheetClose` | root |
| `DialogTrigger` / `DialogClose` | root |
| `DropdownMenuTrigger` / `DropdownMenuItem` | root |
| `TabsTrigger` | root |
| `SelectTrigger` | root |

**Rule:** any time a control must navigate, it uses `render={<Link to="..." />}`. Never wrap a `Button` in a `Link` and never wrap a `Link` in a `Button`.

| Prop | Type | Default | Description |

The consumer's primary decision unit. Everything needed to decide "walk there or not" without opening detail.

| Prop | Type | Required | Description |
| --- | --- | --- | --- |
| `item` | object | ✅ | Denormalised view model — the card never fetches |
| `onSelect` | `(id: string) => void` | — | Used when the card opens a `Sheet` rather than navigating |
| `href` | `string` | — | When present the whole card renders as a `Link` |

**Layout (default)**

```
┌────────────────────────────────┐
│ [−45%]              [3 tersisa]│  ← overlay badges on 4:3 image
│         (photo 4:3)            │
├────────────────────────────────┤
│ Roti Sourdough            🕐   │  text-base font-semibold, truncate
│ Toko Roti Semarang · 450 m     │  text-sm text-muted-foreground
│ Rp12.000  Rp22.000 (struck)    │  PriceDisplay
│ [Vegetarian] [Tanpa Babi]      │  DietaryTagList, max 2 + overflow
│ Ambil 17.00–21.00 · 2 j 15 mnt │  PickupWindowBadge
└────────────────────────────────┘
```

**States**

| State | Trigger | Treatment |
| --- | --- | --- |
| Available | `status === 'active'`, `quantityRemaining > 2` | Full colour, all affordances |
| Low stock | `quantityRemaining <= 2` | Quantity badge `bg-residual-muted`, label `Tinggal N` |
| Expiring soon | `pickupEndMs - now < 60 min` | `PickupWindowBadge` urgency `soon` |
| Sold out | `status === 'sold_out'` | Image `opacity-60`, `StatusBadge`, not tappable |
| Expired | `status === 'expired'` | `opacity-60`, grayscale image, `Kedaluwarsa` badge |
| Loading | — | `RescueItemCardSkeleton` |
| No image | `imageUrl` absent | Category glyph on `bg-muted` + category name |

**Accessibility**

- Entire card is a single `Link` — one tab stop, one announcement, not a nest of links.
- Accessible name: `"{title}, {merchantName}, {currentPrice}, {distance}"`.
- Image `alt="Foto {title} dari {merchantName}"`.
- Overlay badges have `aria-hidden` where duplicated in the accessible name.
- Countdown updates use `aria-live="off"` — a per-second live region would flood a screen reader.

**Usage**

```tsx
<div className="grid gap-4 sm:grid-cols-2 lg:grid-cols-3 md:gap-6">
  {items.map((item) => (
    <RescueItemCard key={item.id} item={item} href={`/item/${item.id}`} />
  ))}
</div>
```

### 5.3 `PriceDisplay`

```tsx
export interface PriceDisplayProps {
  originalIdr: number;
  currentIdr: number;
  size?: "sm" | "md" | "lg";
  showDiscount?: boolean;
  className?: string;
}
```

| Size | Current price | Original | Discount badge |
| --- | --- | --- | --- |
| `sm` | `text-sm font-semibold` | `text-xs line-through` | `text-xs` |
| `md` | `text-base font-semibold` | `text-sm line-through` | `text-xs` |
| `lg` | `text-2xl font-bold` | `text-base line-through` | `text-sm` |

**Rules:**

- Current price first, in `text-foreground`. Original second, `line-through text-muted-foreground`.
- Discount = `Math.round((1 - current/original) * 100)`, rendered `−45%` with a true minus (U+2212), not a hyphen.
- If `current >= original`, render current only and suppress the discount — never show `−0%` or a negative discount.
- If `current === 0`, render `Gratis` in `text-rescued`.
- Accessible name: `"Harga sekarang Rp12.000, harga asli Rp22.000, diskon 45 persen"`.
- Never colour the current price green. Green is reserved for impact semantics; colouring price green implies "cheap = impact", conflating two different meanings.

### 5.4 `PickupWindowBadge`

```tsx
export type PickupUrgency = "upcoming" | "open" | "soon" | "closing" | "closed";

export interface PickupWindowBadgeProps {
  startMs: number;
  endMs: number;
  nowMs?: number;          // injectable for tests
  showCountdown?: boolean;
  className?: string;
}
```

| Urgency | Condition | Tokens | Label |
| --- | --- | --- | --- |
| `upcoming` | `now < start` | `bg-secondary text-secondary-foreground` | `Mulai 17.00` |
| `open` | `start ≤ now`, `> 60 min` left | `bg-rescued-muted text-rescued-muted-foreground` | `Ambil 17.00–21.00` |
| `soon` | 15–60 min left | `bg-residual-muted text-residual-muted-foreground` | `Tersisa 45 mnt` |
| `closing` | < 15 min left | `bg-destructive/10 text-destructive` | `Tersisa 8 mnt` |
| `closed` | `now > end` | `bg-muted text-muted-foreground` | `Ditutup` |

`closing` is the **only** legitimate destructive-token usage outside of destructive actions: the consumer is about to lose money they already paid, so the strongest available signal is warranted. This exception is documented here and nowhere else.

Always leads with a `Clock` icon (`size-3.5`, `aria-hidden`).

### 5.5 `CountdownTimer`

```tsx
export interface CountdownTimerProps {
  targetMs: number;
  onExpire?: () => void;
  format?: "long" | "short";     // "2 jam 15 menit" | "2 j 15 mnt"
  announceThresholds?: number[]; // default [1800000, 600000, 300000]
  className?: string;
}
```

| Remaining | `long` | `short` |
| --- | --- | --- |
| > 1 day | `2 hari 3 jam` | `2 h 3 j` |
| > 1 hour | `2 jam 15 menit` | `2 j 15 mnt` |
| < 1 hour | `45 menit` | `45 mnt` |
| < 5 min | `4:32` | `4:32` |
| Expired | `Waktu habis` | `Habis` |

**Implementation rules:**

- One `setInterval` per mounted instance; cleared on unmount.
- Tick at 60s above one hour, 1s below — a per-second tick for a 6-hour countdown wastes battery on the target Android device.
- `tabular-nums` prevents digit-width jitter (inherited from `body`).
- `aria-live="polite"` fires **only** at `announceThresholds`, never every tick.
- Calls `onExpire` exactly once.
- Never animates. Text simply changes.

```tsx
    expiresAtMs?: number;
```

| Status | Card affordances |
| --- | --- |
| `offered` | `Terima` (primary) + `Tolak` (outline), response countdown, `border-primary` |
| `accepted` | `Catat berat masuk` |

### 9.3 `OutcomeForm`

```tsx
export interface OutcomeFormProps {
  batchId: string;
  acceptedWeightGrams: number;
  onSubmit: (values: OutcomeFormValues) => Promise<void>;
}

const outcomeSchema = z
  .object({
    outputType: z.enum(["bsf_larvae", "compost", "biogas", "animal_feed"], {
      message: "Pilih jenis hasil pengolahan",
    }),
    outputWeightGrams: z.coerce.number().int().min(0),
    residualWeightGrams: z.coerce.number().int().min(0),
    processedAtMs: z.coerce.number().int(),
    note: z.string().max(280).optional(),
  })
  .refine((v) => v.residualWeightGrams <= acceptedWeightGrams, {
    message: "Residu tidak boleh melebihi berat yang diterima",
    path: ["residualWeightGrams"],
  })
  .refine((v) => v.outputWeightGrams + v.residualWeightGrams <= acceptedWeightGrams * 1.05, {
    message: "Total hasil dan residu melebihi berat yang diterima",
    path: ["outputWeightGrams"],
  });
```

| Output type | Label (ID) | Icon |
| --- | --- | --- |
| `bsf_larvae` | `Maggot BSF` | `Bug` |
| `compost` | `Kompos` | `Sprout` |
| `biogas` | `Biogas` | `Flame` |
| `animal_feed` | `Pakan Ternak` | `Beef` |

**The `residual ≤ accepted` constraint is the integrity backbone of the whole impact model.** Without it a processor could log residual exceeding intake, producing a negative recovered weight and a circularity rate above 100% — precisely the impossible number the product must never display.

The second refine allows a 5% tolerance on output + residual versus accepted, because processes like biogas and BSF conversion legitimately lose mass to water and respiration. Anything beyond 5% is flagged for review rather than silently accepted.

A live summary strip above the submit button shows, as the user types:

```
Diterima 2.400 g → Hasil 1.850 g (77,1%) · Residu 400 g (16,7%) · Selisih proses 150 g (6,3%)
```

Submitting writes `outcome_logged` and `residual_logged` and moves the batch to `processed`.

## 10. Planned Components — Shared Infrastructure 📋

### 10.1 `EmptyState`

```tsx
export interface EmptyStateProps {
  icon: LucideIcon;
  title: string;
  description: string;
  action?: { label: string; onClick?: () => void; href?: string };
  secondaryAction?: { label: string; onClick: () => void };
  size?: "sm" | "md";
  className?: string;
}
```

| Rule | Detail |
| --- | --- |
| Icon 24px in a `bg-muted` circle | No illustrations — bytes against the FCP budget, and they rarely survive dark mode |
| Title ≤ 6 words | Scannable |
| Description exactly one sentence | Explains *why* it is empty |
| One primary action max | Two competing actions in an empty state is a decision the user cannot make |
| Distinguish no-data from no-results | Different causes need different actions (see `DESIGN.md` §12.2) |
| Vertical padding `py-16` | Signals a state, not a rendering bug |

### 10.2 `ErrorState`

```tsx
export interface ErrorStateProps {
  title?: string;            // default "Gagal memuat data"
  description?: string;
  onRetry?: () => void;
  variant?: "inline" | "page";
  errorCode?: string;        // shown small, for support

```

| Rule | Detail |
| --- | --- |
| Name what failed | `Gagal memuat item terdekat`, never `Terjadi kesalahan` |
| `Coba lagi` retries the query | Not a page reload |
| Never expose stack traces or vendor codes | Log them; show a human sentence |
| `errorCode` optional, `font-mono text-xs text-muted-foreground` | Support reference only |
| `inline` variant is scoped | A failed map does not blank the list beside it |
| `AlertTriangle` in `text-destructive` | This *is* a legitimate destructive-token use — something genuinely broke |

| Rule | Detail |
| --- | --- |
| Confirm label is a verb | `Batalkan pesanan`, never `Ya` / `OK` |

| `requireTypedConfirmation` for the severest actions | e.g. typing a listing name before deleting a listing with active orders |


| Condition | Behaviour |
| --- | --- |
| Not authenticated | Redirect to `/login` with a `returnTo` param |
| Authenticated, wrong role | Redirect to that role's home, with a Sonner explanation |

**Redirect, do not hide.** Rendering an empty shell for a wrong-role user is confusing and leaks route structure. Wrapping route groups rather than individual components keeps the auth decision in one place per role.

## 13. Implementation Priority

Mapped to roadmap milestones M1–M8. See [`../business/ROADMAP.md`](../business/ROADMAP.md).

| Milestone | Theme | Components | Rationale |
| --- | --- | --- | --- |
| **M1** | Foundation | Font fix (DD-02), token migration prep | Nothing else is stable until type and tokens are correct |
| **M2** | Design system | `StatusBadge`, `SummaryCard` variants, `EmptyState`, `ErrorState`, `LoadingSkeleton`, `RoleGuard`, brand ramp migration (DD-01) | Every later component depends on these; emerald removal is a merge gate |
| **M3** | Consumer discovery | `RescueItemCard`, `PriceDisplay`, `PickupWindowBadge`, `CountdownTimer`, `DietaryTagList`, `DistanceLabel`, `RescueItemDetail`, `SortSelect`, `FilterSheet` | The first screen judges see |
| **M4** | Map & location | `MapView`, `MerchantMarker`, `LocationPermissionPrompt` | Heaviest dependency; isolated so a Mapbox delay does not block the reservation flow |
| **M5** | Reservation & payment | `QuantityStepper`, `ReservationSheet`, `PaymentStatusPanel`, `PickupCodeCard`, `PickupCodeInput`, `OrderCard`, `OrderTimeline`, `ConfirmDialog` | Completes the RESCUED path end to end |
| **M6** | Circular routing | `RecoveryBatchCard`, `IntakeForm`, `OutcomeForm`, `CapacityMeter` | Completes the RECOVERED path — the core innovation |
| **M7** | Impact & ledger | `ImpactStatCard`, `ImpactBreakdownBar`, `CircularityGauge`, `EstimatedBadge`, `LedgerTimeline`, `LedgerEventRow` | The credibility layer; requires real ledger data from M5–M6 |
| **M8** | Admin & polish | `VerificationBadge`, admin moderation and dispute components, a11y audit (DD-09, DD-10), reduced motion (DD-12) | Depends on everything above |

**Sequencing rationale.** M2 before M3 because building cards against emerald hardcodes means rebuilding them. M4 after M3 because the card grid works without a map but a map without cards shows nothing. M7 after M5–M6 because impact components rendered against mock data would violate Measured Honesty and would need rewriting once wired to Convex — better to build them once, against real ledger events.

**Demo-critical minimum.** If time runs short, the irreducible set for a credible DSDC ANFORCOM demo is: `RescueItemCard`, `PickupCodeCard`, `IntakeForm`, `OutcomeForm`, `ImpactBreakdownBar`, `LedgerTimeline`. Those six tell the whole material-flow story: list → collect → route → process → account → prove.
