# Second-pass ruling 9 supplement: how common is KSH_ARRAYS, and does completion work under it?

Added by the recording session on 2026-10-05, when the ruling was shown again during the reading of rule 6 and the user asked: "in this case, zsh autocompletion is a feature is supported, so in a way it must support zsh. Is `KSH_ARRAYS` a common feature of zsh? Is it also a common feature that does not break autocompletion generally?" Everything here was run or fetched in that session, on zsh 5.8.1.

## How common

Fetched (GitHub code search, files named `.zshrc`):

| Search | Files |
| --- | ---: |
| mention `KSH_ARRAYS` | 159 |
| `setopt ksh_arrays` | 157 |
| `setopt ksharrays` | 143 |
| `setopt autocd`, for scale | 6,352 |
| `setopt extendedglob`, for scale | 3,304 |
| call `compinit` (use zsh completion) | 37,312 |

Read, the first twenty files that mention it (`search-ksh-arrays-zshrc.json`): two turn the option on (`langel/bash-stoof`, `TomJo2000/.dotfiles`); ten turn it off or guard a function against it (`setopt localoptions noksharrays`, `unsetopt KSH_ARRAYS`); eight only mention it in a comment, several to warn about it ("KSH_ARRAYS can cause issues with some plugins", "KSH_ARRAYS: breaks multiple things").

So about 0.4 percent of public zsh configurations that use completion mention the option at all, and about one in ten of those turn it on. It is a valid option that few people set, and people who write zsh code commonly guard against it.

## Does completion generally work under it

- Read, `/usr/share/zsh/functions/Completion/compinit` line 152: zsh's completion system lists `NO_ksharrays` among the options it sets while a completion function runs. Completion functions are shielded from the option by the platform.
- Run: `zsh -f -c 'setopt ksharrays; autoload -Uz compinit && compinit -D -u'` exits 0 with no output, and the completions for `git` and `ls` are registered.
- Run: the completion script of another widely used tool, `gh completion -s zsh` (generated by the cobra library, which many command-line tools use), sourced after `compinit` with the option on: exit 0, no output, `gh` registered. Its last lines (`gh-completion-tail.zsh`) use the same unbraced `$funcstack[1]` test as ripgrep's new check, inside a string comparison, which does not print an error.

So completion in general works under the option. ripgrep's new script works under it too (first dossier: completion registers and Tab completes) and differs only in printing one error line, from the arithmetic test `(( ! $+functions[compdef] ))`.
