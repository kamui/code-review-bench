# Podman and Vetto recommendation for issue #35

Investigated 2026-10-05 in response to [the Vetto maintainer's comment on #36](https://github.com/kamui/code-review-bench/issues/36#issuecomment-5999903801). Source inspection targets Vetto v0.6.0, commit `be19bad1e273863b4312364573c6839fa2c266b3`. This is a documentation and source assessment, plus a read-only host capability query. Vetto was not installed or executed, and no new client fixture or performance comparison was run.

## Recommendation

Keep [#35](https://github.com/kamui/code-review-bench/issues/35) on rootless Podman. Investigate Landlock as an additional Linux filesystem boundary around the whole native client inside the container. Vetto demonstrates relevant implementation ideas, but its default policy and credential architecture do not satisfy this epic. The claim of identical isolation is not established.

Podman supplies the minimal runtime image, namespace boundary and container lifecycle. Our remaining native file-tool restrictions need a separate enforcement argument. Changing the launcher does not by itself settle that argument or the broker, clean-context and resource requirements.

## What this means for our work

The macOS alternative also changes the boundary. Vetto's pinned Seatbelt policy starts with broad filesystem reads and adds specific denies; it does not reproduce the Linux read allowlist. Its process-group cleanup documents a gap for descendants that create a new session. That needs separate conformance work before replacing #35's Linux container in a shared Podman Machine. [Read policy](https://github.com/shleder/vetto/blob/be19bad1e273863b4312364573c6839fa2c266b3/src/sandbox/macos/seatbelt.rs#L31-L55), [cleanup limitation](https://github.com/shleder/vetto/blob/be19bad1e273863b4312364573c6839fa2c266b3/src/sandbox/macos/mod.rs#L173-L183).

The [current fixture](../claude-container-fixture.md) records successful native execution inside rootless Podman, including inner sandbox nesting, nine v3 profiles, workers and dummy broker controls. It also records real setup costs: UID helpers, an updated OCI runtime and missing delegated cgroups. Those observations support improving setup diagnosis. They do not establish production admission, and this investigation does not change that status.

The remaining file-route coverage question concerns native tools operating inside the container. Podman does not distinguish allowed review data from other files deliberately mounted inside the same attempt. Landlock could enforce that distinction independently of each native tool, subject to an explicit policy and demonstrated compatibility.

The read-only `landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)` query returned ABI `3` on this x86-64 WSL kernel, `6.6.87.2-microsoft-standard-WSL2`. ABI 3 includes truncation control but lacks the later TCP, device-ioctl, abstract-socket and signal restrictions. This verifies host API availability only, not installation of a policy inside our hardened container. Keep namespaces and broker controls responsible for their existing jobs. [ABI documentation](https://docs.kernel.org/userspace-api/landlock.html#previous-limitations).

## Proposed epic follow-up

1. Scope a dummy-only Landlock feasibility step within the existing Podman architecture. Apply restrictions before the client starts and require inheritance by workers. Start with the four data roots, then enumerate the minimum runtime, home, temporary-file, seed and broker exceptions. Do not describe a policy with extra readable directories as an exact four-root boundary. Resolve that acceptance conflict before implementing it.
2. Version the fixture policy and attribute controls to each layer. Turning off Claude's inner sandbox will not make a file accessible if Landlock still denies it. Preserve the existing evidence and add a paired control that changes only the new kernel policy. Any revision to #36's negative-control requirement must be explicit. Keep #36 and dependent admission pending until the revised design passes review and live dummy fixtures.
3. Add Landlock ABI and required-right checks to [#39's](https://github.com/kamui/code-review-bench/issues/39) planned doctor if that design is selected. Refuse a required capability mismatch. Keep diagnosing UID mappings, OCI versions, nesting and cgroup delegation; changing launchers would not remove all these host requirements.
4. Preserve [#40's](https://github.com/kamui/code-review-bench/issues/40) credential and ordinary-command separation requirements. Domain allowlisting and masked credentials in logs are insufficient substitutes.
5. Use [#44](https://github.com/kamui/code-review-bench/issues/44) to measure image preparation separately from warm launch, native-client startup, command execution, evidence collection and cleanup. Use the same permissions, workload, enforced limits and concurrency when comparing alternatives. No architecture change should rest on the advertised startup number.

A direct-host Vetto backend would expand the epic's explicit Podman-only scope. Reconsider it only through a separate proposal with equivalent conformance evidence and a reproducibility plan. The useful immediate takeaway is kernel enforcement for the whole client, not an unverified replacement of the existing outer boundary.
